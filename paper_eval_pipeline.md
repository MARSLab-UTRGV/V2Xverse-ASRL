# Paper Evaluation Pipeline (RL-CBF vs Baselines)

This document describes the full evaluation/analysis pipeline for paper results.
It covers what files are used, how to run them, and what outputs are generated.

## 1) Goal

Run fair method comparisons on Town05 routes and produce paper-ready tables and figures for:

- `RL+CBF (adaptive gamma, eval-only)`
- `Fixed CBF`
- `PID-only`

Main benchmark defaults:

- Scenario file: `simulation/leaderboard/data/scenarios/town05_all_scenarios_2.json`
- Routes: all `town05_short_r*.xml` (currently 105)
- Passes: 3

## 2) Files Involved

### 2.1 Run matrix configs

- Main benchmark config: `experiments/paper_eval_town05_main.yaml`
- Checkpoint-stage curve config: `experiments/paper_eval_ckpt_stages.yaml`

### 2.2 Runner

- Orchestration script: `scripts/run_paper_eval.sh`

### 2.3 Aggregation and plotting

- Aggregation: `tools/paper/aggregate_eval.py`
- Plot generation: `tools/paper/plot_eval.py`

### 2.4 Runtime engine (already in repo)

- Evaluator entrypoint called by runner: `simulation/leaderboard/leaderboard/leaderboard_evaluator_rl.py`
- Agent: `simulation/leaderboard/team_code/pnp_agent_e2e.py`
- Agent config template (patched per method): `simulation/leaderboard/team_code/agent_config/pnp_config_rl_cbf.yaml`

### 2.5 Raw metric sources reused

- Route/global eval metrics JSON:
  - `results/.../eval/ego_vehicle_0/results.json`
- RL training logs (not required for eval plots, but useful):
  - `results/.../rl/train_log.csv`

## 3) Prerequisites

- CARLA server running and reachable at the port in config (default `40002`).
- Python dependencies:
  - `pyyaml` (required by `scripts/run_paper_eval.sh` embedded Python)
  - `matplotlib` (required by `tools/paper/plot_eval.py`)
- A valid RL checkpoint path for `rl_cbf_adaptive` method when `rl.eval_only=true`.

## 4) Config Schema (Run Matrix)

Each matrix YAML has:

- `experiment`:
  - `name`: experiment folder name under `output_root`
  - `output_root`: root for run outputs
  - `reference_method`: used for paired deltas (`reference - compare`)
- `runtime`:
  - evaluator/network parameters, route protocol, scenario file, seeds
- `methods`: list of methods
  - `name`
  - `base_agent_config`
  - `overrides`: merged into base config before run

Method definitions in main config:

1. `rl_cbf_adaptive`
   - `rl.enabled=true`
   - `cbf.enabled=true`
   - `rl.eval_only=true`
   - `rl.deterministic_eval=true`
   - `rl.resume_path=<checkpoint>`
2. `fixed_cbf`
   - `rl.enabled=false`
   - `cbf.enabled=true`
3. `pid_only`
   - `rl.enabled=false`
   - `cbf.enabled=false`

## 5) Output Layout Generated by Runner

For experiment `town05_main`:

```text
results/paper_eval/town05_main/
  run_manifest.json
  <method>/
    manifest/
      agent_config_eval.yaml
      matrix_snapshot.yaml
      method_manifest.json
    pass01/
      eval/
        results.json
        ego_vehicle_0/results.json
      images/
      rl/
      manifest/
        command.sh
        eval.log
    pass02/
    pass03/
```

Notes:

- `agent_config_eval.yaml` is the effective per-method config after overrides.
- `command.sh` captures exact evaluator command used for that pass.
- `eval.log` captures evaluator stdout/stderr for the pass.

## 6) How to Run

### 6.1 Start CARLA (default config port)

```bash
CUDA_VISIBLE_DEVICES=0 ./external_paths/carla_root/CarlaUE4.sh --world-port=40002 -opengl
```

### 6.2 Dry-run (recommended first)

```bash
bash scripts/run_paper_eval.sh --config experiments/paper_eval_town05_main.yaml --dry-run
```

This validates config/paths and prints fully resolved commands without running evaluator.

### 6.3 Run full main benchmark

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_paper_eval.sh --config experiments/paper_eval_town05_main.yaml
```

### 6.4 Run one method only

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_paper_eval.sh --config experiments/paper_eval_town05_main.yaml --method pid_only
```

### 6.5 Overwrite existing pass results

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_paper_eval.sh --config experiments/paper_eval_town05_main.yaml --force
```

By default, existing pass results are protected and runner aborts if they already exist.

### 6.6 Checkpoint-stage curve evaluation

```bash
CUDA_VISIBLE_DEVICES=0 bash scripts/run_paper_eval.sh --config experiments/paper_eval_ckpt_stages.yaml
```

## 7) Aggregate Tables

Run from manifest (recommended):

```bash
python3 tools/paper/aggregate_eval.py \
  --manifest results/paper_eval/town05_main/run_manifest.json \
  --output-dir paper_outputs/main
```

Fallback discovery mode:

```bash
python3 tools/paper/aggregate_eval.py \
  --runs-root results/paper_eval/town05_main \
  --output-dir paper_outputs/main
```

### 7.1 Aggregation outputs

- `paper_outputs/main/route_metrics.csv`
  - one row per route execution record
  - includes scores, status, infractions, duration, traveled km, method/pass metadata
- `paper_outputs/main/method_summary.csv`
  - method-level mean/std/95% CI
  - completion rate, collision metrics, infractions per route
- `paper_outputs/main/paired_deltas.csv`
  - paired per-route deltas for `reference_method - compare_method`

## 8) Generate Figures

```bash
python3 tools/paper/plot_eval.py \
  --summary-csv paper_outputs/main/method_summary.csv \
  --paired-csv paper_outputs/main/paired_deltas.csv \
  --output-dir paper_outputs/main/figures
```

### 8.1 Figure files produced (PNG + PDF)

- `overall_scores`
  - driving score and route completion score (mean +- 95% CI)
- `overall_collisions_per_km`
- `infraction_breakdown`
- `paired_delta_hist_<method>`
  - per-baseline histogram of `delta_score_composed`
- `checkpoint_stage_curve`
  - generated only when stage-tagged methods are present

## 9) Metric Conventions

- Paired delta is:
  - `delta = reference_method - compare_method`
- Collision rate:
  - `collisions_per_km = total_collisions / traveled_km`
- 95% CI:
  - `1.96 * std / sqrt(n)`

## 10) Common Failure Modes

1. `rl.eval_only=true` with missing checkpoint
   - Runner fails fast if `rl.resume_path` is empty or file missing.
2. Wrong CARLA port
   - Ensure CARLA world port matches `runtime.port` in matrix YAML.
3. Existing outputs
   - Use `--force` if you intentionally want to overwrite previous pass outputs.
4. Missing Python deps
   - Install `pyyaml` and `matplotlib` in the active env.

## 11) Typical End-to-End Command Sequence

```bash
# 1) Start CARLA
CUDA_VISIBLE_DEVICES=0 ./external_paths/carla_root/CarlaUE4.sh --world-port=40002 -opengl

# 2) Sanity check
bash scripts/run_paper_eval.sh --config experiments/paper_eval_town05_main.yaml --dry-run

# 3) Run benchmark
CUDA_VISIBLE_DEVICES=0 bash scripts/run_paper_eval.sh --config experiments/paper_eval_town05_main.yaml

# 4) Aggregate
python3 tools/paper/aggregate_eval.py \
  --manifest results/paper_eval/town05_main/run_manifest.json \
  --output-dir paper_outputs/main

# 5) Plot
python3 tools/paper/plot_eval.py \
  --summary-csv paper_outputs/main/method_summary.csv \
  --paired-csv paper_outputs/main/paired_deltas.csv \
  --output-dir paper_outputs/main/figures
```

## 12) Quick Checklist Before Running

- `experiments/paper_eval_town05_main.yaml` has correct RL checkpoint path.
- CARLA server is up on configured port.
- Enough disk space for images/eval logs.
- Decide whether to keep or disable per-step image/json outputs in agent config.
